# Published `model_21800`

This repository includes the complete public model bundle used by the build_1
`hitter_pure` deployment line:

| Artifact | Repository path | Purpose |
| --- | --- | --- |
| Training checkpoint | `hope_training/whole_body_tracking/checkpoints/model_21800.pt` | Warm-start/play checkpoint at iteration 21800. |
| Deploy actor | `a3_deploy/a3_deploy_example/models/model_21800/policy/exported/policy.onnx` | The 110-D observation, 31-D action actor used by the deploy runner. |
| Deploy parameters | `a3_deploy/a3_deploy_example/models/model_21800/policy/params/deploy.yaml` | Joint order, action offsets/scales/clips, timing, and PD constants for this actor. |
| Gate 3 video | [`assets/model_21800_gate3_mujoco.mp4`](assets/model_21800_gate3_mujoco.mp4) | Formal build_1 planner + policy-native runner closed loop in the AimRT MuJoCo viewer. |

The ONNX and `deploy.yaml` are the deploy artifacts used by the native build_1
runner. The public checkpoint preserves the model weights, optimizer state and
`iter: 21800` exactly. Machine-bound 6144-environment resume state, private
absolute paths and W&B run identity were removed; it is therefore a standard
warm-start checkpoint, not a byte-identical continuation of the original
machine process.

## Run the deployed actor in MuJoCo

From a fresh clone, only a normal Python virtual environment is required:

```bash
python3 -m venv .venv-mujoco
source .venv-mujoco/bin/activate
python -m pip install -r a3_deploy/a3_deploy_example/reference/requirements.txt

# Headless contract smoke. The default config selects model_21800.
a3_deploy/a3_deploy_example/scripts/run_pingpong_sim.sh --duration 10

# Interactive window at the deployment control rate.
a3_deploy/a3_deploy_example/scripts/run_pingpong_sim.sh --view --realtime
```

The actor has two inputs (`obs[1,110]`, `time_step[1,1]`) and an
`actions[1,31]` output. The public wrapper derives the reference clock from the
current command, translates between the training and SDK joint orders, and
loads the model's exported action and PD arrays. Compact single-input public
exports remain supported through `--onnx`.

The standalone real-ball evaluator remains available for focused policy checks:

```bash
MUJOCO_GL=egl python hope_training/whole_body_tracking/scripts/mujoco_eval_onnx.py \
  --eval-mode independent --num-serves 4 --max-trial-seconds 1.8 --seed 0
```

## Gate 3 closed-loop video

The committed video was recorded from build_1's sole formal entrypoint,
`pp_gate3_hitter_pingpong.sh`, with the published model_21800 policy directory.
It is not the standalone evaluator above. The recorded chain is:

```text
physical MuJoCo ball -> simulated OptiTrack -> production relay -> planner
-> schema-2 command -> policy-native C++ runner -> AimRT MuJoCo plant
```

The runner entered MOTION once and was not reset between shots. Gate 3 invokes
the x86-only `--gate3-qdes-audit-only` option: finite `q_des` is published
unchanged, and `q_des` or measured actual-q limit excesses are recorded as
telemetry instead of terminating the runner. The production default is
unchanged when this explicit Gate 3 option is absent.

In this captured run, all 12 serves engaged and completed, with 12 measured
racket contacts and 12 legal landings. There were no falls or fatal actual-q
faults. The authoritative verdict remains `Gate3=FAIL`: continuous-rally
readiness/recovery, one x-lock check, and the idle-smoothness report did not
pass. The video documents the complete Gate 3 execution path; it is not
presented as a PASS or hardware qualification.

## Load the checkpoint in Isaac Lab

Prepare the A3 asset and training environment as described in
[`QUICKSTART_A3_ISAAC.md`](../QUICKSTART_A3_ISAAC.md), then run:

```bash
cd hope_training/whole_body_tracking
source setup_train_env.sh
hope_isaac_py scripts/play.py task=HOPEPingPong algo=ppo num_envs=4 \
  checkpoint=checkpoints/model_21800.pt
```

The checkpoint is stored through Git LFS. On a fresh clone, materialize it
before launching play:

```bash
git lfs install
git lfs pull --include=hope_training/whole_body_tracking/checkpoints/model_21800.pt
```

Use the same `checkpoint=checkpoints/model_21800.pt` override with the public
`task=HOPEPingPong` recipe to warm-start training. Training is never launched by
the repository setup or deploy scripts.

## What the formal Gate 3 test validates

The formal Gate 3 entry is an x86 MuJoCo closed loop, not an Isaac replay and
not a direct `torch.load()` of the checkpoint. `model_21800.pt` is the training
artifact; deployment necessarily runs its exported actor,
`models/model_21800/policy/exported/policy.onnx`, through the native C++ Runner.
The package builder verifies that the ONNX SHA-256 matches
`params/deploy.yaml` before it permits a Gate 3 run. Loading the `.pt` directly
is covered separately by the Isaac Lab command above.

Gate 3 exercises the complete runtime chain:

```text
MuJoCo physical ball/table/racket
  -> simulated OptiTrack and production relay
  -> production Planner schema-2 command
  -> model_21800 policy-native C++ Runner
  -> AimRT MuJoCo robot plant
  -> measured contact, landing, plant and Runner reports
```

The formal profile contains 12 side-neutral serves. The Planner must select
forehand/backhand from live geometry; the launcher does not command a side.
The explicit x86-only `--gate3-qdes-audit-only` option records finite actor
commands without clipping them so policy behavior remains observable. A
non-finite final `q_des` or measured joint state still terminates the Runner.
This option is not enabled by normal hardware launchers.

## Build and test the native Gate 3 bundle

The commands in this section run on an x86_64 development laptop. They use the
`hope` distrobox because ROS 2 Jazzy is not expected to be installed on the
host. Run each block from the host shell; every block enters the distrobox
explicitly.

First define the clone root once in the host shell. Replace the example path
with the location of this clone:

```bash
cd /path/to/HOPE_OPEN
export HOPE_OPEN_ROOT="$PWD"
```

The public repository does not redistribute AgiBot's licensed Unitree SDK
binary payload. Point `A3_VENDOR_PAYLOAD_ROOT` at an authorized
`a3_deploy_example` payload containing `thirdparty/unitree_sdk2`. This payload
is needed to link the native Runner, but it is not needed for the host-only
Python tests or the MuJoCo contact-model test.

### 1. Host-only source and contract tests

```bash
cd "$HOPE_OPEN_ROOT"

python3 -m pytest -q \
  a3_deploy/a3_deploy_example/tests/test_model21800_gate3_bundle.py \
  a3_deploy/a3_deploy_example/tests/test_pp_gate3_core.py \
  a3_deploy/a3_deploy_example/tests/test_pp_planner_envelope_audit.py \
  a3_deploy/a3_deploy_example/tests/test_pp_rally_conductor_contract.py \
  a3_deploy/a3_deploy_example/tests/test_pp_rally_report.py \
  a3_deploy/a3_deploy_example/scripts/tests/test_pp_mujoco_plant_report.py
```

These tests check the 110-D/31-DOF model contract, ONNX provenance, formal
entry dependency closure, 12-serve Planner envelope, report semantics and
plant-trace scoring. A Git LFS pointer is accepted for `model_21800.pt` because
the native Gate 3 path consumes the committed ONNX actor. To use the checkpoint
in Isaac, materialize it separately:

```bash
cd "$HOPE_OPEN_ROOT"
git lfs pull --include=hope_training/whole_body_tracking/checkpoints/model_21800.pt
```

### 2. Build the ROS Planner workspace

```bash
distrobox enter hope -- env HOPE_OPEN_ROOT="$HOPE_OPEN_ROOT" bash -lc '
  set -eo pipefail
  source /opt/ros/jazzy/setup.bash
  cd "$HOPE_OPEN_ROOT/hope_ws"

  colcon build \
    --symlink-install \
    --packages-select hope_msgs hope_bringup hope_planner \
    --cmake-args \
      -DBUILD_TESTING=OFF \
      -DPython3_EXECUTABLE=/usr/bin/python3 \
      -DPYTHON_EXECUTABLE=/usr/bin/python3
'
```

### 3. Build the model_21800-only native Runner package

Set the vendor payload path before running this block. On a prepared internal
checkout it may already be the public source directory; in a fresh public
clone it should be a separate authorized payload directory.

```bash
export A3_VENDOR_PAYLOAD_ROOT=/absolute/path/to/authorized/a3_deploy_example

distrobox enter hope -- env \
  HOPE_OPEN_ROOT="$HOPE_OPEN_ROOT" \
  A3_VENDOR_PAYLOAD_ROOT="$A3_VENDOR_PAYLOAD_ROOT" \
  bash -lc '
  set -eo pipefail
  source /opt/ros/jazzy/setup.bash
  cd "$HOPE_OPEN_ROOT"

  agibot/code_deployment/a3_deploy_example/scripts/build_a3_deploy_pkg.sh \
    --arch x86_64 \
    --pingpong-only \
    --jobs 12
'
```

`--pingpong-only` deliberately excludes unrelated legacy A3 policies and
debug tools. The resulting package contains the model_21800 Runner, its ONNX
and deploy metadata, ONNX Runtime, Unitree DDS libraries, AimRT iceoryx/ROS 2
plugins and custom ROS message libraries. Packaging fails if any required file
is absent or if the ONNX SHA does not match `deploy.yaml`.

### 4. Build and unit-test the Gate 3 MuJoCo plant

The first configure downloads the pinned AimRT and MuJoCo source dependencies.
Later builds reuse `_deps/`. The build directory has a formal, unversioned
name; it is ignored by Git.

```bash
distrobox enter hope -- env HOPE_OPEN_ROOT="$HOPE_OPEN_ROOT" bash -lc '
  set -eo pipefail
  source /opt/ros/jazzy/setup.bash

  sim="$HOPE_OPEN_ROOT/a3_deploy/A3_MuJoCo_Sim/aimrt_mujoco_sim"
  build="$sim/cmake-build-model21800-gate3"

  cmake -S "$sim" -B "$build" \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_INSTALL_PREFIX="$build/install" \
    -DAIMRT_MUJOCO_SIM_BUILD_TESTS=ON \
    -DAIMRT_MUJOCO_SIM_BUILD_WITH_ROS2=ON \
    -DAIMRT_MUJOCO_SIM_ENABLE_COVERAGE=OFF \
    -DPython3_EXECUTABLE=/usr/bin/python3 \
    -DPYTHON_EXECUTABLE=/usr/bin/python3

  cmake --build "$build" -j12
  ctest --test-dir "$build" --output-on-failure
  cmake --install "$build"
'
```

### 7. Run the formal 12-serve Gate 3 closed loop

Run this only in a dedicated `hope` distrobox session with no other MuJoCo,
Runner, Planner or iceoryx session active. The script owns its scoped test
processes and cleans them up when it exits.

```bash
distrobox enter hope -- env HOPE_OPEN_ROOT="$HOPE_OPEN_ROOT" bash -lc '
  set -eo pipefail
  source /opt/ros/jazzy/setup.bash
  cd "$HOPE_OPEN_ROOT"

  a3_deploy/a3_deploy_example/scripts/pp_gate3_hitter_pingpong.sh
```

Set `PP_VIEWER=1` before the entrypoint if an interactive MuJoCo window is
required. The authoritative outputs are:

| Output | Meaning |
| --- | --- |
| `/tmp/pp_rally_report.json` | Per-serve and final Runner/Planner verdict. |
| `/tmp/pp_physical_ball_report.json` | Measured contacts and legal landings. |
| `/tmp/pp_mujoco_plant_report.json` | Plant timing, state and command evidence. |

| `/tmp/pp_runner.log` | Native Runner log and transitions. |

A successful process exit means the formal report accepted the complete
qualification contract; a preflight PASS alone is not a Gate 3 PASS.

## Native runner and planner reference

The model directory already has the layout consumed by the build_1 C++ runner:

```text
models/model_21800/policy/
├── exported/policy.onnx
└── params/deploy.yaml
```

After building `a3_deploy_onnx_ref_pingpong`, select the public
transport/runtime config and pass that directory as `--policy-dir`:

```bash
cd a3_deploy/a3_deploy_example
source setup_a3_env.sh
cmake -S . -B build
cmake --build build --target a3_deploy_onnx_ref_pingpong -j

# The source-tree build writes the executable under dist/. Start in PASSIVE;
# --planner selects the build_1 schema-2 latest-snapshot planner path.
dist/a3_deploy_x86_64/a3_deploy_onnx_ref_pingpong \
  --runtime-cfg src/a3/a3_deploy_onnx_ref/config/a3_runtime_config.pingpong.hitter_pingpong.yaml \
  --policy-dir models/model_21800/policy --planner --policy-native \
  --start passive --official-stand
```

That is the public equivalent of the model selection in the build_1 field
procedure; site addresses, operator login details and session logs are
deliberately not published. The source Runner, Planner and model bundle are
open, while actual A3 motor I/O still requires the separately licensed AgiBot
vendor runtime. Operators must retain their vendor e-stop, limits and hardware
procedure; this document does not auto-start motion or bypass robot protections.

The source and published model artifacts are released under the repository
license. AgiBot-provided files retain the notices and licensing stated in
[`A3_ASSETS.md`](../A3_ASSETS.md).
